# 部署与运维

面向运营方：服务端怎么装、显示屏怎么批量装、日常怎么用怎么升级、出了问题怎么查。
系统设计与取舍（为什么这么做）见 [architecture.md](architecture.md)，硬件选型见 [hardware.md](hardware.md)。
设备装好后很难再物理接触，所以除首次装机外的一切变更都能在管理后台远程完成。

## 1. 取得成品包

部署用的一切都在**每个角色一个自包含压缩包**里，拷过去解开即可安装。两个包里都带 `INSTALL.md`，现场不用带着仓库也能装。

### 1.1 本地构建

```sh
make package
# → bin/display-agent-<版本>-armv7.tar.gz    设备端程序包（程序 + 安装/更新/回滚脚本 + systemd 单元）：装机与 OTA 都用它
# → bin/display-server-<版本>-<架构>.tar.gz  服务端（二进制 + systemd 单元 + 配置 + make-image.sh）
```

版本号取自 `git describe`（也可 `make package VERSION=1.2.0`），注入设备端程序：后台从程序里读版本，包名也用它。
`make build` / `make agent-arm` 只产出裸二进制，供本地调试。

**离线依赖包**：设备播放所需的 GStreamer 等 Debian 软件包连同全部依赖（一两百 MB）。后台上传一次，之后装机与 OTA
都从服务端局域网安装依赖，又快又不需要外网（原理见 architecture.md 第 5 节）：

```sh
make deps                  # 默认 trixie；须与设备 Armbian 的 Debian 版本一致，如 Ubuntu 系的 make deps DEBIAN=noble
# → bin/display-deps-<代号>-armhf.tar.gz
```

需要 docker 和能跑 arm 容器的 qemu（`apt install qemu-user-static`）。依赖清单只有一份（`deploy/agent/deps.txt`）；
它变了或想用上 Debian 的安全更新时重新打包上传即可。

### 1.2 从 GitHub 下载（本机没有 Go 环境时）

仓库配了 GitHub Actions（`.github/workflows/ci.yml`）：

- **每次 push**：跑 gofmt/vet/测试，并把两个成品包作为 Actions 构建产物上传（保留 90 天）；
- **推送 `v*` 标签**：自动创建 Release，附上两个成品包，以及 trixie、noble 两个版本的离线依赖包
  （手动运行 CI 也会打依赖包）。

```sh
git tag v1.2.0 && git push origin v1.2.0     # 随后在 Releases 页面下载
```

标签名就是包名与程序内置版本，OTA 据此判断设备是否已升到目标版本。

> 服务端包按 Actions 运行器的架构（amd64）构建。服务器是 ARM 的话在本地 `GOOS=linux GOARCH=arm64 make package-server`。
> CI 产物里的 `server.json` 是占位口令，见 2.1。

## 2. 服务端部署（运营方本地服务器）

安装步骤（拷包、装字体/ffmpeg/poppler、systemd 单元）写在服务端包里的
[`deploy/server/INSTALL.md`](../deploy/server/INSTALL.md)。装好后是一个**自包含目录**：二进制、配置、内容、状态、字体
全在里面，整个目录拷走即可搬迁。

```
/srv/display/
  display-server      二进制
  server.json         配置
  fonts/              渲染用字体
  data/               服务端状态（首次启动自动创建）：
    state.json          设备（含属性、显示配置、更新目标）、模板、程序包、设备访问、管理口令哈希
    cache.json          文件缓存区索引（见 5.2）
    media/<设备ID>/     该设备的播放内容（后台上传，也可直接拷进来）
    media/.store/       文件缓存区：处理好的内容各存一份，设备目录里是指向它的硬链接
    packages/           上传的设备端程序包
    deps/<代号>/        离线依赖包（装机与 OTA 用的 apt 仓库）
    backgrounds/        模板底图
    thumbs/             缩略图与视频抽帧（30 天没用自动清理）
    rendered/           模板/测试卡的渲染结果
    incoming/           上传与处理的暂存区（启动时清空）
    tls/                服务端证书与私钥
```

**配置里的相对路径按 `server.json` 所在目录解析**，与进程工作目录无关——systemd 启动服务时工作目录是 `/`，
若按工作目录解析，`"data"` 会悄悄落到 `/data`。要用 FHS 布局就在配置里写绝对路径，并相应改 `display-server.service`。

`server.json` 字段（样例里只写了要改的几项，其余用默认值）：

| 字段 | 说明 |
|---|---|
| `admin_token` | 管理后台的初始/找回口令（见 2.1、2.2）。必填：留空或是样例里的占位值时服务端拒绝启动 |
| `enroll_token` | 设备注册口令，同上；新设备装机时在一键装机命令里输入 |
| `font_path` | CJK 字体文件路径（是文件不是目录），缺失则中文渲染成方框 |
| `timezone` | 服务端的时区（IANA 名称，如 `Asia/Shanghai`），留空取服务器系统时区。测试卡按它显示；设备的系统时区也跟着它（一个轮询周期内生效，设备上 `date`、journalctl 的时间即与服务端一致）。服务端时区数据已内嵌，不依赖系统 tzdata |
| `listen` | HTTPS 主端口，默认 `:9001`：管理后台、设备通信都走这里 |
| `bootstrap_listen` | HTTP 装机端口，默认 `:9000`：**只**提供一键装机脚本和程序包，其余请求一律 301 跳到 HTTPS |
| `media_root` | 各设备播放内容的根目录，默认 `data/media` |
| `data_dir` | 服务端状态，默认 `data` |
| `poll_interval_s` | 设备轮询间隔，默认 10 秒（1~300）。决定后台改动多快上屏、多快发现设备离线（约 3 个周期没来即离线，至少 30 秒）。**所有设备照这里的值执行**：随每个响应下发，改完重启服务端即可 |
| `heartbeat_interval_s` | 设备心跳间隔，默认 60 秒（10~3600）。心跳只上报健康数据，不影响在线判断 |
| `ffmpeg_path` | 可选，ffmpeg 路径；留空在**服务进程的** PATH 里找。不可用时不能上传视频（排查见 INSTALL.md） |

图片停留时长不在这里配置——它是版式的一部分，写在模板里，在管理后台改。

**端口与证书**：防火墙放行 TCP 9001（设备、管理后台）与 9000（新设备装机）。管理后台在 `https://<服务器>:9001/admin`。
服务端首次启动在 `data_dir/tls/` 生成长期有效的自签证书，所以浏览器第一次会提示"连接不是私密连接"：把 `server.crt`
导入管理电脑并设为信任，不要养成点"继续访问"的习惯——局域网里有人冒充服务端时，浏览器的警告是唯一的提醒。
设备不靠 CA 校验，而是**固定证书公钥指纹**（装机时自动写进设备的 `agent.json`），指纹打印在服务端启动日志里，
后台「管理」页也有。

> **`data_dir/tls/` 要和 `state.json` 一起备份。** 证书丢了重新生成，指纹就变了，所有已装设备都会拒绝连接
> （日志里是 `server certificate fingerprint ... does not match tls_fingerprint`），只能逐台改 `agent.json`。

### 2.1 两个口令从哪来

`make package` 会在本地生成一次并长期沿用，写在 `.secrets/tokens.env`（已 gitignore，`make clean` 不会删）。
8 位字母数字，含大小写与数字，不带符号——这两个值要写进 JSON、经环境变量传给脚本、还要在浏览器里手敲。

```sh
make tokens     # 查看当前口令；文件不存在时生成
```

打出来的**服务端包里的 `server.json` 已经填好这两个口令**，所以这个包本身要当机密对待；设备端包里不含口令，
装机人员在一键装机命令里输入 `enroll_token`。

| 口令 | 用途 | 改了会怎样 |
|---|---|---|
| `admin_token` | 登录管理后台（初始口令；之后可在后台修改，见 2.2） | 重新登录即可，无其他影响 |
| `enroll_token` | 新设备注册的凭证，装机时输入；也用于下载装机用程序包 | **已注册的设备不受影响**（它们用的是各自的密钥），之后装机用新口令即可；插卡即装镜像要重做 |

> **公开仓库**：CI 构建**不会**把真实口令打进产物——否则它们会随 Release 附件公开。从 Releases 下载的包里是占位值
> `change-me`，服务端带着占位值会直接拒绝启动并提示你生成。

### 2.2 管理口令：修改、找回、锁定

- **修改**：「管理」页的「管理口令」卡片。服务端只存 PBKDF2 哈希，改完后 `server.json` 里的 `admin_token`
  只是一段失效的旧值。
- **忘了口令**：登录服务器，把 `server.json` 的 `admin_token` 改成一个**新值**（例如 `openssl rand -base64 9` 生成），
  然后 `systemctl restart display-server`：新值立即生效，后台改过的口令作废。改回以前用过的同一个值不会触发。
- **猜错锁定**：按来源地址统计不同的错误口令，前 5 个不锁，之后依次锁 1 分钟、5 分钟、15 分钟、1 小时（之后每次 1 小时），
  锁定期间口令对也进不去；验证成功、24 小时没再猜错、服务端重启都会清零。同一个错口令反复出现（浏览器拿着旧口令自动刷新）
  只算一次。失败与锁定都写进 `journalctl -u display-server`（`admin auth failed from …`）。
- **浏览器**：默认只在当前标签页记住口令，关掉即忘；勾选「记住这台电脑」才长期保存，右上角【退出】清除（【管理】页也在右上角）。
- `server.json` 设成只有服务账号可读（`chmod 600`）。

### 2.3 设备是怎么登记的

没有"在配置里登记设备"这回事——设备一律凭 `enroll_token` 自注册：首次上电时自己确定编号（规则见 4.1）、生成随机密钥、
向服务端注册，随后出现在后台设备列表里。同一编号用不同密钥再注册会被拒（409），防止冒名顶替；这种请求会显示在后台
该设备上，核对无误可一键「接受新密钥」（见 6.3）。

## 3. 设备端：装机（公版 Armbian + 一键安装）

目标硬件：Orange Pi One（全志 H3，1GB，百兆网，HDMI）+ LCD 1440×900（HDMI 驱动板）。台数多时用插卡即装镜像（4.2）。

### 3.1 烧录 Armbian

1. 从 [Armbian 官网](https://www.armbian.com/orange-pi-one/) 下载 Orange Pi One 的
   **Trixie CLI（minimal 或 standard）** 镜像（Debian 13；离线依赖包默认也打 trixie，二者要一致）；
2. 用 balenaEtcher 写入 TF 卡（建议**工业级/高耐久** TF 卡，≥16GB）；
3. 首次上电走初始化向导（设 root 密码，普通用户可跳过），配好网络；
4. 想用主机名当设备编号（如 `scr-0017`，见 4.1）就在这时 `hostnamectl set-hostname scr-0017`，不设也行。

### 3.2 固定 HDMI 输出为 1440×900 并禁用息屏

面板的 EDID 往往把 1920×1080 报成首选模式，**要在两个地方都指定**，`install-agent.sh` 会一并写好：

| 位置 | 内容 | 管什么 |
|---|---|---|
| `/boot/armbianEnv.txt` 的 `extraargs` | `video=HDMI-A-1:1440x900@60 consoleblank=0 cma=256M` | 内核控制台的输出模式；`consoleblank=0` 禁用息屏；`cma=` 连续内存（硬解要用） |
| `/etc/display-agent/agent.json` | `"display_mode": "1440x900"` | 播放进程设置的显示模式 |

只改第一处是不够的：**播放进程自己设置显示模式，不理会内核的 `video=` 参数**，不指定就用 EDID 的首选模式，
于是控制台是 1440×900、一播放内容又变回 1080p。显示屏不提供 `display_mode` 这个模式时，代理退回首选模式（日志里会提示）。

驱动板 EDID 里压根没有 1440×900 时，内核会忽略 `video=`，该模式也不会出现在可用列表里。
这时加 `,e` 强制输出：装机命令里加 `HDMI_FORCE=e`（即 `video=HDMI-A-1:1440x900@60,e`）。
改完要**重启**（一键安装会自动重启）。输出分辨率最终不一致也不会错位，只是缩放（见 architecture.md 4.2），但仍应配对。

### 3.3 一键安装

前提：管理后台「管理」页**已上传过设备端程序包**（装机下载的就是当前的那个）；建议同时上传**离线依赖包**，
没有它时每台设备都要从外网 apt 下载上百 MB 依赖，境外源常常要十几分钟甚至失败。

在设备上以 root 运行（后台「管理」页的"新设备装机"里有这条命令，地址已填好）：

```sh
curl -fsSL http://<服务器>:9000/install.sh | ENROLL_TOKEN=注册口令 sh
```

它会：设备时钟没校准时按服务端时间校一下 → 凭注册口令下载程序包 → 写 `/etc/display-agent/agent.json` 与服务端证书 →
按 OTA 布局安装、装依赖（服务端有对应版本的离线依赖包时只从局域网装，日志 `从服务端离线依赖仓库安装`）→
写 HDMI/CMA 启动参数 → `systemctl enable display-agent` → 10 秒后**自动重启**。重启后设备自动注册，1~2 分钟内出现在后台。
可选参数（`HDMI_MODE`、`HDMI_FORCE`、`CMA`、`NO_REBOOT`）与手工安装（连不到 9000 端口时）见
[`deploy/agent/INSTALL.md`](../deploy/agent/INSTALL.md)。

出错时的提示：`注册口令不对`、`服务端还没有上传设备程序包`、`连不上服务端`（查网线、IP、9000 端口防火墙）、
`缺少依赖 …`（上传与设备 Debian 版本一致的离线依赖包，或让设备能上外网）。

`install-agent.sh` 的行为要知道：**每次运行都会重写** `agent.json`（换服务端重跑一遍装机命令即可）；设备编号与密钥在
`/var/lib/display-agent/identity.json`，不受影响；装完直接 enable 服务，开机即进入播放，需要进控制台时插 USB 键盘按任意键（3.5）。

### 3.4 确认分辨率、硬件解码与温度

```sh
/usr/local/lib/display-agent/check-display.sh
```

逐项检查并给出处理办法，有问题时退出码为 1：

| 项 | 怎么判断 | 不对时的现场表现 |
|---|---|---|
| 内核输出模式 | 已连接的显示接口是否提供 `display_mode`（在全部逐行扫描模式里找） | 播放时退回首选模式，画面按比例缩放 |
| 硬件解码条件 | cedrus 已加载；播放进程用的 Python GStreamer 绑定里查得到 `v4l2slh264dec` 与 `kmssink`；内核参数里的 `cma=` 生效了 | 视频退化成软解：发热、卡顿，严重时过热关机；CMA 太小时视频放不出来 |
| 实际播放状态 | 代理每个心跳周期写的 `/var/lib/display-agent/status.env`（连不上服务端时也写）：解码器、输出分辨率 | — |
| SoC 温度 | `/sys/class/thermal/thermal_zone0/temp` | 85°C 起降频，再高关机 |

解码方式、输出分辨率、温度也随心跳上报，**管理后台设备列表里直接能看到**：软解与 80°C 以上标红，
输出分辨率与模板画布不一致时标黄。

### 3.5 现场救援：不知道设备 IP、屏幕又被播放画面占着

设备能连上服务端时，后台设备列表里就有它的 IP，直接 SSH 即可。连不上服务端时：

1. 给设备插上 **USB 键盘，按任意键**；
2. 播放暂停，屏幕切到控制台（tty1），顶部显示设备编号、主机名、全部 IPv4、MAC、服务端地址、
   与服务端的连接状态和最近一次错误、程序版本；下面就是登录提示，可直接登录 root；
3. 键盘 **15 分钟**不动自动恢复播放。要更久就在控制台里 `systemctl stop display-agent`，排查完再 `start`。

不需要任何网络。只认真正的键盘（有字母键、回车、空格），红外遥控、板载按键不会误触发；随时插拔都行。
恢复播放时会重启 tty1 的登录程序，留在控制台上的会话随之注销。**样机上确认一次**：按键后控制台确实出现（不是黑屏）。

## 4. 设备端：批量部署

### 4.1 设备编号规则

代理首次启动按以下优先级确定编号，并持久化到 `/var/lib/display-agent/identity.json`：

1. **主机名**——装机前 `hostnamectl set-hostname scr-0017` 即为设备编号；
2. 主机名是公版默认值（`orangepione` 等）时，取 SoC 序列号后 8 位 → `opi-1a2b3c4d`（再退回网卡 MAC）。

不设主机名也没关系：规则 2 保证编号唯一，在后台给设备加个属性（如 `location=3楼大堂`）便于辨认。
密钥在首启随机生成，只存在于设备与服务端两处；`enroll_token` 仅用于首次注册。

### 4.2 插卡即装镜像

服务端包里的 `make-image.sh` 往**公版 Armbian 镜像**里加一个首次开机服务，做成装机镜像，所有 TF 卡烧同一个，插卡上电就自动装机、
注册，不用接键盘、不用登录。在 Linux 上以 root 运行（镜像只有一个 ext4 分区，要挂载它，Windows/macOS 改不了；服务器本身就可以）：

```sh
BOOTSTRAP=http://<服务器>:9000 ENROLL_TOKEN=<注册口令> ROOT_PASSWORD=<设备 root 密码> \
  ./make-image.sh Armbian_<版本>_Orangepione_trixie_current_<内核>_minimal.img.xz
# → Armbian_..._minimal-display.img：用 balenaEtcher 烧到每张 TF 卡
```

可选 `HDMI_MODE`、`HDMI_FORCE`、`CMA`，含义同一键装机。它对镜像只做三件事：

- 设好 root 密码（装机期间现场控制台登录用；后台「设备访问」设置过 root 密码的话，设备注册后换成那个，见 9.1），
  并跳过 Armbian 的首次登录向导与它的自动登录——无人值守时向导会一直卡住；
- 写入 `display-firstboot` 服务：首次开机等网络就绪后执行一键装机，进度显示在 HDMI 屏幕上和 `journalctl -u display-firstboot` 里；
  连不上服务端、口令不对等失败时每 30 秒重试；
- 装机成功后删除这个服务与镜像里带的注册口令文件，然后重启进入播放。

上线流程：插卡 → 接屏、接网 → 上电 → 约 5~10 分钟后（服务端已上传离线依赖包时；否则取决于外网速度）
设备出现在后台设备列表 → 设属性（如 `room=302`）、在【内容】里上传要播的内容 → 点【测试】确认是哪块屏。

注意：镜像里带着注册口令和 root 密码的哈希，**当作机密保管**；镜像不含程序本身，装的永远是服务端上当前的程序包，
程序更新后不用重做镜像；设备 Debian 版本由所用的 Armbian 镜像决定，离线依赖包要与之一致；首次开机装机在样机上确认一遍再批量烧录。

## 5. 日常运维（管理后台）

服务端首次启动会自动建好一个"左右分屏"模板（左边房间号、右边播放内容）并设为全局默认，开箱就能用。
页面每 10 秒自动刷新设备列表等只读区域（打开对话框、或页面在后台标签页时暂停），正在编辑的全局模板选择不会被冲掉。

### 5.1 内容与设备列表

- **设备列表**页每行【内容】：这台设备要显示什么都在这一个对话框里——
  - 模板：跟随全局，或给这台设备单独指定一个（可以"复制全局模板再改"，底图不复制）；
  - **左右对调**：同一个模板，把属性放到另一边；
  - 播放内容：点选或把文件拖进上传框，选中的文件**立即出现在列表里**、各自显示上传进度，逐个上传；上传、转码过程中
    就可以拖动条目调整顺序（电脑上按住左侧把手拖；iPhone/iPad 上按住把手直接拖，或长按条目"拿起"再拖；键盘焦点在把手上时可用 ↑↓）。
    **增删与排序即时生效**；模板和左右对调要点【保存模板设置】。按顺序循环播放，图片停留时长跟着模板走，视频播完即切，一律静音；
    条目之间约 0.6 秒淡出到黑再淡入；
  - **预览当前效果**：把播放列表的一项（默认第一项，多于一项时可选）铺进媒体区、盖上模板与底图，与设备上看到的一致；
    视频取它的一帧（需要 ffmpeg）。模板列表里的【预览】只看版式，媒体区是空的；
- **设备列表**页每行【属性】：`room=302` 之类的键值对，模板的 attribute 区域按 key 取值显示；
- **模板**页：新建/编辑时勾选「属性区」「媒体区」，勾了才出现对应设置；两个都勾时拖动中间的分隔条调两区宽度
  （一边缩小另一边自动扩大）。属性文字水平居中，可设相对中心的上下偏移（px，负数上移）。更复杂的版式用【JSON】，
  之后再用表单编辑只写回表单里改过的值，JSON 里改的其余内容保留。另有【底图】（5.3）；全局默认模板在页面顶部的下拉框里选。
  模板至多有一个"播放内容"区域；只剩一个模板时不显示【删除】，删掉当前的全局模板时全局自动改指向剩下的模板；
- **管理**页（右上角）用顶部的分段控件分两组，一次看一组（记住上次看的那组）：**设备**（程序更新与离线依赖包、
  新设备装机、亮度、设备访问）与**服务端**（管理口令、存储）；后台所有时间都是 24 小时制；
- 生效延迟 ≈ `poll_interval_s`（默认 10 秒）。

**设备列表各列**：

| 列 | 内容 | 多久更新 |
|---|---|---|
| 状态 | 在线/离线；离线时显示最后在线时间 | 设备列表每 10 秒刷新 |
| 设备 | 编号、主机名/IP、程序版本（→ 目标版本），以及**解码方式 · SoC 温度 · 实际输出分辨率**；红字"程序更新失败"/"访问设置失败"悬停看原因 | 设备每次心跳（默认 60 秒） |
| 当前显示 | **等待刷新**（后台改了内容，设备还没来取）→ **正在刷新**（设备在下载新内容）→ **已显示最新内容**；下面一行是内容来源与模板名 | 设备每次轮询（默认 10 秒） |

设备的任何请求（轮询、心跳、下载文件）都算联系过，下载文件期间只要数据还在传也一直算；约 3 个联系周期
（轮询与心跳间隔中较短的那个，默认 30 秒）没有任何联系就显示离线。

### 5.2 上传与文件缓存区

| | 处理 | 为什么 |
|---|---|---|
| 图片 | png/jpg ≤ 20MB；超过 1440×900 的**自动等比缩小** | 设备只有 1GB 内存；在服务端缩一次，所有设备都省 |
| 视频 | mp4/mov/mkv/webm 等 ≤ 500MB，**一律转码**为设备吃得消的 H.264（1440×900 以内、≤ 30fps、码率封顶 4Mbps、静音） | 原片动辄 10~20Mbps，持续高码率即使硬解也会发热，到 85°C 降频、更高直接关机。参数与取舍见 architecture.md 4.4 |
| PDF | ≤ 50MB、≤ 100 页，**逐页渲染**成图片（需服务端装 `poppler-utils`），设备上逐页当图片轮播 | 设备只认图片和视频；页面与媒体区方向不一致时会被裁掉一部分，后台卡片上会提示 |

视频转码、PDF 渲染在**后台串行**进行：上传后立即返回，列表里显示"转码中 xx%"/"转换中 3/12 页"，完成后按你排好的位置加入播放
（未完成前不会下发给设备）；失败（有密码的 PDF、损坏、超限等）显示原因，可删除重传。
**ffmpeg 不可用时不能上传视频**（poppler 不可用时不能上传 PDF），后台顶部会提示原因，排查见 `deploy/server/INSTALL.md`。

**文件缓存区**（「管理」页的存储）：处理好的内容在服务端各存一份，设备目录里是硬链接。删除文件、删除设备后内容留在缓存区里；
之后再上传同一个原片（不论哪台设备）**直接复用**，立即就绪、不再转码，列表里标"已复用"。缓存区默认 16GB：超过配额时
从最久没用的内容开始自动清理，设备正在播放的永远不清；配额不能小于设备在用文件的总大小。在用文件已占满配额时新上传会被拒收，
需要先调大配额或删除不用的内容。媒体目录所在的文件系统不支持硬链接（如 exFAT 移动硬盘）时自动改为复制。

### 5.3 模板底图（给设计师的清单）

节日主题等模板画不出来的画面：模板页每个模板的【底图】。设计原理见 architecture.md 4.3。

- 尺寸等于模板画布（默认 1440×900），**只收 PNG**，≤ 20MB；比例不同时等比铺满后居中裁切；
- 底图**压在播放内容上方**：**媒体区里要透明**，视频/图片从透明处露出；不透明的装饰（相框、灯笼、边角花纹）会压在视频上。
  媒体区完全不透明的会被拒收，透明不到一半时上传成功但会提示。对话框里写着媒体区坐标，【下载参考图】给出画布原尺寸的参考图
  （媒体区标红、文字/属性区域标框），设计时当作最上面的参考图层；
- 装饰集中在媒体区的边角最好：切换内容时的淡入淡出要逐行处理压进媒体区的装饰；
- 属性/文字区域的「底色」留空时透明，文字直接叠在底图上——设计时给这些区域留出干净、对比度够的位置；
- 开了左右对调的设备用**对调版底图**：另做一张、媒体区在另一侧（对话框里有对调版的坐标和参考图）。没传对调版时
  对调的设备用原图，模板列表和设备的内容对话框里会提示。

节日期间把全局模板切到节日模板，结束后切回；设备一个轮询周期内换上。

### 5.4 现场定位

**设备列表**页每行【测试】→ 选 1/5/15 分钟：该屏全屏显示"测试"卡片（含设备编号与属性），到期自动恢复。
测试卡与正常内容走同一套分发管线，测试成功本身就验证了整条链路。

### 5.5 程序 OTA

「管理」页的**程序更新**上传设备端程序包 `display-agent-<版本>-armv7.tar.gz`，不用填版本号——服务端从程序里读出，并当场校验
（是 linux/arm 的 Go 程序、注入了版本号、`update.sh` 与 `install-agent.sh` 都在），不符即拒收、不会下发。
服务端**只保留一个程序包**：上传新版本即替换旧版本（旧文件删除），还在等待更新的设备改为更新到新版本（定时不变），
已经更新到位的设备不受影响。它同时也是新设备一键装机下载的包。点【下发】，选择立即或定时、全部或指定设备；
【取消所有待更新】撤销尚未执行的下发。从多版本的旧服务端升级上来后，要重新上传一次程序包。设计细节见 architecture.md 第 5 节。

- 设备下载、校验、执行包内 `update.sh` 后切换，后台显示"程序版本 → 目标版本"，两者一致即完成；
- `update.sh` 失败（非零退出或超过 15 分钟）：不切换，继续跑旧版本，设备列表里红字"程序更新失败"，5 分钟后自动重试；
- 新版本连续 3 次启动失败：自动回滚到上一个版本（程序和脚本一起），**这个版本不再自动重试**，设备列表里显示
  "版本 X 连续 3 次启动失败，已回滚"；修好后用新的版本号重新上传下发；
- **新版本需要新的软件包**：加进 `deploy/agent/deps.txt`，重新 `make deps` 并上传离线依赖包，再上传、下发程序包。
  `update.sh` 先装上新增的软件包，装不上就失败、不切换，后台显示"缺少依赖 …"。重新打的依赖包里有 Debian 的安全更新时，
  下一次 OTA 也会顺带升级已装的软件包。

安装布局（`/usr/local/lib/display-agent/`）：

```
versions/<版本>/        整包解开（程序 + 脚本）；只保留 current 与 previous 两个版本
current -> versions/…   systemd 从 current/display-agent 启动
previous -> versions/…  回滚目标
pending-verify          新版本待确认（rollback-check.sh 计启动次数）
failed-version          回滚掉的版本（不再自动重试；撤销下发或下发别的版本时清除）
rollback-check.sh       固定路径（update.sh 安装）
check-display.sh        -> current/check-display.sh
```

**OTA 能改什么、不能改什么**——这条边界决定了哪些改动要提前想清楚：

| | 内容 |
|---|---|
| 程序包 OTA 即可 | 播放逻辑（含随代理分发的播放进程）、清单新字段的解析、下载与缓存策略、心跳内容；新增或升级软件包（`deps.txt` + 离线依赖包）；以及 `update.sh` 能做的系统调整：systemd 单元、启动参数、配置文件 |
| 还需同时更新服务端 | 清单生成、模板渲染、管理后台界面（服务端在机房，更新它不用去现场） |
| **OTA 做不到** | 换 Armbian 的 Debian 大版本、换内核（要重刷）；把设备从本服务端迁走（`server_url`、证书指纹写在设备的 `agent.json` 里——`update.sh` 技术上能改，但改错了设备就再也连不回来） |

`update.sh` 的约定：幂等；软件包只在它里面装；对版本目录以外的改动要与上一个版本兼容——回滚只切回旧版本目录，
**不会撤销** `update.sh` 做过的系统改动（包括装上的软件包）。新增设备端配置项时仍要让"缺省值即可用"。

### 5.6 亮度

「管理」页的**亮度**：设若干时段，每段一个亮度（10%~100%，每档 10%）和是否**播放媒体区**，所有设备统一执行，
不在任何时段内时为 100%、正常播放。例如 18:00–22:00 70%、22:00–07:00 30% 且不播放媒体区
（时段可以跨午夜，不能重叠，最多 8 段）。

- 按**服务端时区**判断（`server.json` 的 `timezone`，留空取服务器系统时区）；设备的时钟与时区都跟随服务端；
- 保存后设备一个轮询周期内学到新的时段，之后**到点自己切换**（每 30 秒检查一次），断网也照样按时调暗、恢复；
  时段存在设备本地，断网重启后照旧；
- 调的是**画面亮度**：播放器在整屏最上层叠一层黑幕，属性区、底图、图片、视频一起变暗，切换内容的淡入淡出照常；
  显示器背光不变，所以全黑处的漏光不会减少；
- 关掉「播放媒体区」的时段：当前的图片/视频淡出后停播，媒体区黑着，属性区照常（亮度可以仍是 100%）；
  时段结束后从下一项接着播；
- 设备日志里有切换记录：`journalctl -u display-agent | grep brightness`
  （如 `agent: brightness 30%, media area off (period 22:00-07:00)`）。

## 6. 排障

先看日志：设备上 `journalctl -u display-agent -n 80`，服务端 `journalctl -u display-server -f`。服务端只记自己在做什么
（不刷设备心跳），日志一律英文；后台界面上给运营方看的提示是中文。例如：

```
upload done: device scr-0017, promo.mov (186.4MB in 21.3s), queued for processing as promo.mp4
transcode done: device scr-0017, promo.mp4 (186.4MB -> 19.2MB in 1m22s), added to playlist
new content pushed: device scr-0017, version 3f9a…, 4 file(s) + template overlay
device scr-0018 online (192.168.1.58, agent 1.3.0)
```

### 6.1 注册成功，但轮询/心跳报 401 unauthorized

签名请求带时间戳，服务端只认与自己相差 ±5 分钟以内的（防重放）。服务端日志（`grep 'auth rejected'`）和设备日志都写明原因：

| 原因 | 说明 | 处理 |
|---|---|---|
| `clock skew: device time …, server time …` | 设备时钟偏了（Orange Pi One **没有 RTC**，断电重启后要等 NTP） | 代理自动按服务端时间签名并校准系统时钟（日志 `agent: system clock set from the server`）；设备已由 NTP 同步而仍偏，说明是服务器时间不准 |
| `bad signature` | 设备密钥与服务端登记的不一致 | 见 6.3 |
| `unknown device` | 设备在后台被删除了 | 代理会自动重新注册成一台新设备 |

### 6.2 轮询/心跳报 connection reset by peer / EOF

这是 TCP 连接被对端断开，不是认证问题（认证失败一定是 401 并写明原因）。代理每次请求失败后都会丢掉旧连接、下次用新连接重试。
仍然持续出现时按顺序查：

1. `server_url` 指向的确实是 display-server（端口被别的程序占用时服务端起不来：`ss -ltnp | grep 900`）；
2. 服务端日志里有没有 `http: panic serving`，有的话把那几行发给开发；
3. 服务器的防火墙（ufw、firewalld、fail2ban）有没有拦设备的 IP；
4. 局域网里有没有 IP 冲突。

### 6.3 设备报"在服务端登记的是另一把密钥"

通常是 `/var/lib/display-agent/identity.json` 丢了：重装系统、换了 SD 卡、手工删过这个目录。设备继续播放本地缓存，
同时把新密钥报给服务端。处理：后台该设备上的红色提示 →【核对并处理】→ 对照硬件序列号 / MAC，以及设备日志里
`agent: new identity … key=xxxxxxxx` 的指纹 → 一致就点**接受新密钥**，设备一分钟内重新注册成功，**属性、播放列表、专属模板都保留**
（不要用"删除设备"来解决，那会把这些配置一起删掉）。不一致说明是另一台机器撞了编号（给其中一台改主机名）或有人冒充，点忽略。

设备日志每次启动都打印身份来源：`using existing identity …`（正常）或 `new identity …`（首次启动，或身份文件丢了）。
身份文件损坏时另存为 `identity.json.bad-<时间>` 留作证据；同一缓存目录只允许一个代理进程。

### 6.4 硬解没起来、媒体区不出画面

`check-display.sh` 第 2 项不过时：`ls /dev/video* /dev/media*` 有没有 cedrus 的设备、`dmesg | grep -i cedrus` 有没有报错
（如 CMA 内存不足）、`gstreamer1.0-plugins-bad` 装了没有；改完后 `rm -rf /root/.cache/gstreamer-1.0` 让 GStreamer 重新扫描插件。

媒体区不出画面时看设备日志：每一项第一次显示时记 `showing <文件> (<类型>, <源尺寸 格式>, crop …)`；放不出来记
`cannot play <文件>: <原因>`；视频输出方式退一步记 `video output '…' failed: … retrying with '…'`；GStreamer 自己的 ERROR 行
（以及 `kmssink`、`v4l2codecs` 的 WARN 行）也在其中。播放进程接连起不来（如 HDMI 没接）时重启间隔逐步拉长到 1 分钟。

视频没铺满媒体区时，看每段视频开播一秒后的 `video plane: dst …, src …` 一行（`check-display.sh` 第 3 项"视频图层"同样内容）：
`dst` 应等于模板媒体区，不等时行尾会注明 `not filling it`。播放进程启动时的 `display …` 一行若带
`pixel aspect N/D (compensated)`，说明显示器 EDID 报的物理尺寸与输出分辨率比例不一致（如 16:9 的屏跑 1440×900），
播放进程已经抵消了 kmssink 因此做的比例校正。

## 7. 服务端升级与数据迁移

服务端的全部可变状态只有 **`data_dir`** 和 **`media_root`**，自包含布局下都在 `/srv/display` 里。

| 路径 | 内容 | 要不要保留 |
|---|---|---|
| `data/state.json` | 设备（含密钥）、属性、模板、全局设置、程序包元数据、更新目标、设备访问、管理口令哈希 | **必须** |
| `data/tls/` | 服务端证书与私钥 | **必须**。丢了重新生成指纹就变了，已装设备全部拒绝连接 |
| `data/media/` | 各设备的播放内容与文件缓存区 | **必须** |
| `data/backgrounds/` | 模板底图 | **必须**（模板引用它们） |
| `server.json` | 配置（含两个口令） | **必须**。另外把 `.secrets/tokens.env` 也备份到构建机之外 |
| `data/cache.json` | 文件缓存区索引 | 建议（缺了缓存区里的内容无法复用，会重新转码） |
| `data/packages/` | 上传的设备端程序包 | 建议（否则待下发的更新目标会失效，新设备也没有包可装） |
| `data/deps/` | 离线依赖包 | 不必，可重新上传；缺了装机与 OTA 退回在线安装 |
| `data/rendered/`、`data/thumbs/` | 渲染结果、缩略图 | 不必，按需重新生成 |

**原地升级**：先 `cp -a /srv/display/data /srv/display/data.bak`（`cp -a` 保留硬链接），再停服务、换二进制、启动：

```sh
systemctl stop display-server && cp display-server /srv/display/display-server && systemctl start display-server
```

**换一台服务器**：`tar czf display-backup.tar.gz -C /srv display`，在新机器上解开到同样位置，装好 systemd 单元后启动。
`state.json` 是原子写入，热备份也是一致的；停机只是为了避免拷贝过程中有人刚好在改配置。

> **搬迁前务必确认两件事**：
> 1. 设备 `agent.json` 里的 `server_url` 写死在每台设备上，服务器换 IP 就要逐台改。所以**从一开始就用域名而不是 IP**
>    （例如 `https://display.lan:9001`），搬迁时只改 DNS。一键装机脚本里的地址取自装机命令里用的主机名，所以装机命令里就写域名。
> 2. `data/tls/` 一起搬过去，证书指纹不变，设备才认新服务器。

**定期备份**：

```sh
tar czf /backup/display-$(date +%F).tar.gz -C /srv display --exclude='display/data/rendered' --exclude='display/data/thumbs'
```

`data/media/` 里的设备文件与 `data/media/.store/` 是硬链接，`tar` 原样保留（只存一份）；改用 rsync 时要加 `-H`。

## 9. 安全与访问

| 通道 | 保护 |
|---|---|
| 设备 ↔ 服务端（9001） | HTTPS；设备**固定服务端证书公钥指纹**，不依赖 CA，也不校验有效期和主机名——设备时钟不准、服务器换 IP 都不影响，冒充的服务端拿不出同一把私钥就连不上 |
| 设备请求的身份 | 每台设备一把随机密钥，请求带 HMAC 签名（时间戳 ± 5 分钟防重放）；设备只能取自己目录下的文件 |
| 管理后台（9001） | HTTPS + 共用管理口令（服务端只存哈希、猜错按来源地址阶梯锁定，见 2.2）；页面带 CSP，只许连本服务端、不许被别的网页嵌入 |
| 装机入口（9000，HTTP） | 只有一键装机脚本（不含口令，只含服务端地址、证书指纹与证书）和程序包下载（凭注册口令）；其余请求 301 到 HTTPS |

剩余的风险与取舍：

- 装机那一刻的脚本走明文 HTTP：局域网内能做中间人的人可以篡改它。装机在受控的现场进行，可接受；
  介意的话用手工安装（见 `deploy/agent/INSTALL.md`），从后台复制证书指纹。
- 程序包不做额外签名：服务端本身被攻破时可以下发任意程序包。服务端要按内网关键服务器对待（`server.json`、
  `data_dir/tls/server.key` 不外泄）。
- 设备不开防火墙：设备本身不监听任何端口（代理只主动连服务端），唯一的入口是 SSH，由下面的「设备访问」管住。

### 9.1 设备访问（root 密码、SSH 公钥）

在「管理」页的**设备访问**卡片里设置：root 密码与 SSH 公钥是两张卡片、各自保存。保存后在线设备一个轮询周期内生效，离线设备上线即生效：

- **root 密码**：现场插键盘的控制台登录用。服务端只存哈希，页面上只显示设置时间。这里没设置过时，设备保持装机时的密码
  （插卡即装镜像里的 `ROOT_PASSWORD`，或烧录后手工设的）；
- **SSH 公钥**：每行一个（运维电脑上 `ssh-keygen -t ed25519` 生成，整行复制 `~/.ssh/id_ed25519.pub`）。配了公钥后
  设备**只允许密钥 SSH**、密码 SSH 关闭；清空公钥则恢复密码 SSH。设备上的 authorized_keys 整份由这里决定，
  已配过公钥的设备再下发新公钥也没问题（每次整份重写）；
- **人员变动**：删掉他的公钥、必要时重设 root 密码，保存即可；**换运维电脑**：私钥就是一个文件，可以安全地拷过去，
  更推荐在新电脑上生成新密钥、把新公钥加上、旧公钥删掉；
- 设备应用失败时设备列表里红字"访问设置失败"，鼠标悬停看原因，设备每分钟重试。

设备还会关掉 apt 的定时任务、锁定内核与 dtb/u-boot 包，不会自己升级系统。

## 10. 无外网运行

服务端安装时要联网（装 ffmpeg、字体等）；设备装机在服务端有离线依赖包时只需局域网。**安装完成后整个系统只需要局域网**：
服务端、设备端、管理后台都不访问外网——没有云服务、在线授权、CDN 或外部字体，管理后台的页面资源全部内嵌在服务端里。

### 10.1 已经处理掉的离线问题

| 情况 | 不处理会怎样 | 现在的做法 |
|---|---|---|
| 设备没有 RTC、连不上外网 NTP，时钟偏了 | 签名请求全部 401，设备收不到任何更新 | 设备按服务端响应里的时间签名，并把自己的系统时钟校到服务端时间 |
| 局域网 DNS 是路由器转发到运营商，外网一断域名就解析不了 | 设备找不到服务端 | 设备记住上次实际连上的地址（`/var/lib/display-agent/server-addr`），解析失败时用它 |
| 服务端暂时连不上（服务器关机、交换机故障） | 重试的等待超过看门狗 90 秒，代理连同播放进程被杀，屏幕每隔一分半黑一下 | 等待期间持续喂看门狗；屏幕一直播放本地缓存 |
| 设备开机时网络还没就绪（网线没插、DHCP 拿不到地址） | 服务要等 network-online 超时（最长约 2 分钟），这期间黑屏 | 不等网络，开机立即播放本地缓存，网络就绪后再注册、拉清单 |
| 服务端卡住或网络时断时续 | 一个请求能挂 10 分钟，看门狗把代理杀掉 | 清单/心跳/注册 30 秒超时；大文件下载按"60 秒没收到数据"判定停滞，下次从断点续传 |
| 环境变量里带着指向外网的代理 | 局域网请求被送去连不上的代理 | 设备端一律直连 |
| 服务器没装 tzdata 包，`server.json` 写了 `timezone` | 服务端拒绝启动 | 时区数据内嵌在服务端程序里 |

### 10.2 仍需注意的地方

- **服务器时钟**：测试屏到期、定时下发程序都按服务器时间计算。服务器断网后时间会慢慢漂移且没人察觉；
  管理后台每次打开都会拿浏览器所在电脑的时间比对，相差 2 分钟以上会在顶部提示。设备的时钟由代理自动校到服务器时间。
  手工校准：`date -s "2026-10-02 09:30:00"` 后 `hwclock -w`。
- **server_url 用的域名**：设备**第一次注册时**必须能解析（局域网 DNS 静态记录，或在设备的 `/etc/hosts` 里写死）。
  之后 DNS 失效会用缓存的地址；但服务器换了 IP 而 DNS 又不可用时，设备找不到新地址。
- **服务器安装完成后不能再装软件**：ffmpeg、CJK 字体、poppler 要在安装时装好。
- **程序升级**：在一台能联网的机器上 `make package`（或下载 Release），把程序包拷到局域网里的电脑，再从管理后台上传、下发。
- **设备依赖**：上传了与设备 Debian 版本一致的离线依赖包时装机与 OTA 完全离线；否则设备那时要能访问 Armbian/Debian 软件源。
  离线依赖包在一台能联网、装了 docker 的机器上 `make deps`（或从 Release 下载）。
